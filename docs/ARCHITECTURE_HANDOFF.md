# Architecture ground truth for diagramming

Written for an agent that must draw the StepperMotorController firmware architecture
(graph, chart, Mermaid, whatever) from how the code is **actually** built.
Everything below was measured from the source tree on 2026-10-05 after Phase 3
(commits `b21e275`..`f537d72` on `master`). Where the code disagrees with the markdown
docs, this file says so.

Do not use `CODE_PHILOSOPHY.md`, `README.md` or anything under `docs/archive/` as a
source of nodes or edges. They describe intent. Use this file plus the two generated
files it points at.

## 0. Primary machine-readable inputs

| File | What it is | Trust level |
|---|---|---|
| `docs/architecture_manifest.json` | 9 sheets with full file lists, 6 harnesses, 35 signals with provider/flow/timing/context/ownership, 4 tasks, 2 global nets with measured includer counts | Generated by `scripts/gen_architecture.py` from the `constexpr SignalDesc[]` tables in `server/harness/defs/*.hpp`. The signal tables are hand-written C++ constants, so they are *declared* truth, cross-checked by `scripts/check_harness_defs.py` against the struct members. |
| `docs/ARCHITECTURE.md` | Same content as Markdown plus a Mermaid diagram | Same generator |

**Harness internals worth drawing separately** (they are not one homogeneous box):

- `harness/defs/` — the six boundary headers. Each is one struct of references plus a
  signal table plus (except H_TASKS_L3) one `connect*()` declaration. All `connect*()`
  bodies, and **every** tap application, are in `harness/defs/harness_connect.cpp`
  (`connectL4L5`, `connectL3L4`, `connectL1L2`, `connectL2L3`, `connectL5L1Bytes`,
  `connectSPIManager`).
- `harness/pins/` — 41 files, no forwarders left (checker rule 8 forbids them). PODs
  (`MotorCommand`, `AsyncEvent`, telemetry types, pin bundles, `SeqSnapshot<T>`), init
  contracts (`clock_board`, `spi_init`, `comms_board`, `*_driver_init`, `platform_board`,
  `early_debug_board`), `IResponseSink`, the EXTI callback table, the µs-clock accessor.
- `harness/taps/` — `TracedLock`, `TracedSPIBus`, `TracedMotorDriver`, `TracedTransport`,
  `TracedEncoder`, applied via `applyTap<Tap, Slot, Iface>()`. Compiled only with
  `ENABLE_INTERFACE_TRACE` (on in `firmware-debug`, off in `firmware-release`).
- `harness/trace/interface_trace.{hpp,cpp}` — the `ITRACE(...)` macro and sink. A **global
  net** like Platform (documented as such since step 8): included directly by 7 L3 files,
  2 L2 files and 6 harness files. No-ops in release.

## 2. Declared boundary edges (the six harnesses)

Full per-signal rows are in the manifest. Summary of what each struct actually carries:

| Harness | Header | Struct members (real) | Signals | Connect |
|---|---|---|---|---|
| H_L1_L2 | `harness_l1_l2.hpp` | `Transport::ITransport& transport` | 1 | `connectL1L2(raw)` wraps with `TracedTransport` |
| H_L2_L3 | `harness_l2_l3.hpp` | `const L3Dispatchers& dispatchers` (13 refs: motion, config, safety, queue, controlMode, supervisorTrim, encoder, motorDriver, display, flash, system, trace, debug) + `Protocol::ICommandProcessor& processor` | 14 | `connectL2L3(dispatchers, processor)`, no taps |
| H_L3_L4 | `harness_l3_l4.hpp` | 7 pointers: `IMotorDriver* motor`, `ICanvas* canvas`, `IJoystick* joystick`, `IFlash* flash`, `IEncoderHardware* encoderHw`, `IConfigStore* configStore`, `IDebugAccess* debug` (nullptr = absent) | 7 | `connectL3L4(clock)` runs the 5 L4 init contracts, taps `TracedMotorDriver`, `TracedEncoder` |
| H_L4_L5 | `harness_l4_l5.hpp` | `MotorPins*`, `LCDPins*`, `JoystickPins*`, `FlashPins*`, `EncoderPins*`, `IInternalFlash*`, `IBoardDebug*`, `registerExti` fn ptr | 8 | `connectL4L5()` runs the 5 L5 init contracts, taps `TracedSPIBus` slots 0 (SPI1) and 1 (SPI2) |
| H_L5_L1 | `harness_l5_l1_bytes.hpp` | `Transport::IByteChannel& channel` | 1 (`exception: true`) | `connectL5L1Bytes(CommsChannel)` runs L5 `initCommsBoard`; **called from L1** (`transport_init.cpp`) |
| H_TASKS_L3 | `harness_tasks_l3.hpp` | no struct; the 4 `I*Service` interfaces by include | 4 (`Provider: Lower`, `Flow: Down`: tasks above L3) | no connect; SYSTEM hands each service to `Scheduler::init*Task` |

Direction convention in the manifest: `down` = toward hardware / toward L3 from the tasks,
`up` = toward host. Since step 4 every harness has the same orientation: the upper sheet
calls down into the provider.

Power-net connection outside the six harnesses: `Harness::connectSPIManager(spi1, spi2)`
(declared in `pins/spi_init.hpp`, defined in `harness_connect.cpp`) applies the two
`TracedLock` taps to the Platform mutexes and calls the L5 `initSPIManager` contract.

## 3. Measured include edges (what the compiler sees)

Counted with a script over every `#include` in `server/` (vendor excluded), grouped by
sheet. Self-includes and C standard headers dropped. "pins" = `harness/pins/`.
"defs:X" = that specific harness header. "trace" = `harness/trace/`.

```
L1  -> defs:harness_l5_l1_bytes.hpp 1 | pins 2
L2  -> defs:harness_l1_l2.hpp 3 | defs:harness_l2_l3.hpp 2 | pins 9 | trace 2
L3  -> defs:harness_l2_l3.hpp 3 | defs:harness_l3_l4.hpp 31 | pins 39 | trace 7 | PLATFORM 20
L4  -> defs:harness_l4_l5.hpp 13 | pins 8 | PLATFORM 2
L5  -> defs:harness_l4_l5.hpp 5 | defs:harness_l5_l1_bytes.hpp 3 | pins 9 | PLATFORM 1 | CMSIS/FreeRTOS/SEGGER 16
TASKS    -> defs:harness_tasks_l3.hpp 4 | pins 6 | PLATFORM 14
PLATFORM -> pins 22 | CMSIS/FreeRTOS/SEGGER 22
SYSTEM   -> L3 7 | TASKS 6 | PLATFORM 1 | pins 6 | defs:harness_l5_l1_bytes.hpp 1
defs     -> L1 2 | L2 1 | L3 17 | L4 7 | L5 7 | PLATFORM 2 | pins 14
pins     -> PLATFORM 9   (pins include NO layer header any more)
taps/trace -> L1 1 | L3 1 | L4 2 | L5 1 | pins 1
```

Key reading: **no layer includes another layer's directory directly**, and `harness/pins/`
no longer reaches into any layer. Every L↔L edge goes through `harness/defs/`.
L3 no longer includes `harness_tasks_l3.hpp` (the checker forbids it); only the task sheet
and SYSTEM see that header. `check_includes.py --strict` reports 0 violations.

### 3a. Edges that cross layers through a pins forwarder

None. The 36 one-line forwarders were deleted in step 6; `check_harness_defs.py` rule 8
fails on any pins file that includes a layer `boundary/` or `F_platform/tasks/` header.
The two former cross-layer uses now go through their harness header:
L5 → `harness_l5_l1_bytes.hpp` for `IByteChannel` (rule 3), L2 → `harness_l1_l2.hpp` for
`ITransport`.

## 4. Composition and init order (from `server/main.cpp` + `system_init.cpp`)

```
main()
  System::initHardware()
    Harness::initClockBoard()                      [L5 init/clock_board.cpp, via pins/clock_board.hpp]
    Harness::initDebugOutput()                     [PLATFORM hw/early_debug_board.cpp, namespace Harness]
    Platform::initMicrosecondClockTIM5()           [PLATFORM hw/microsecond_timer_tim5.cpp]
    Services::TickTimer_Init(usClock)              [L3 infra/tick_timer]
    Harness::setMicrosecondClock(&usClock)         [pins/imicrosecond_clock.cpp, global accessor]
    Trace::initTraceSink()                         [L3 infra/trace -> Harness::ITrace::setSink]
  System::initPlatform()
    Harness::initPlatformBoard(s_platform)         [PLATFORM rtos/platform_init.cpp] 6 mutexes + 2 queues + clock/scheduler/stats/critical/notifier
    Harness::connectSPIManager(*spi1Lock, *spi2Lock)   [harness_connect.cpp: TracedLock<0/1> taps -> L5 initSPIManager -> Board::g_spiManager]
  System::initServices()
    Platform::setTaskStatsProvider(r.taskStats)
    Services::initSystemServices(controlModeLock, eventQueue, telemetryLock, uiModeLock, clock)   [L3 motion/system_service_init.cpp]
  System::initTasks()
    Services::initMotorSubsystem(motorCmdQueue, clock, commandQueueLock, taskStats, out)
        connectL3L4(clock)  --(first call)--> L4 init contracts --> connectL4L5() --> L5 init contracts
        g_motorService.init(...) ; g_commandQueue.init(...)            -> out.motorService, out.motorCtrl
    Scheduler::initMotorTask(*out.motorService, motorCmdQueue, clock, scheduler)      [TASKS: creates the Motor task]
    Services::initEncoderSubsystem(clock, critical, usClock, out)        -> connectL3L4 (cached); out.encoderService or nullptr
    Scheduler::initEncoderTask(...)   only when out.encoderService != nullptr (else "SKIP")
    Services::initDisplaySubsystem(clock, out)                           -> connectL3L4 (cached); out.displayService, displayControl, remoteDisplay
    Scheduler::initDisplayTask(...)
    Services::initCommsSubsystem(deps, clock, out)
        connectL3L4 (cached) ; g_debugService.init(debug, motorCtrl, displayControl)
        initDispatches(...) -> L3Dispatchers
        Protocol::initCommsProtocol(out, dispatchers, clock)                     [L2]
            Transport::initTransport(out, VCP_UART, clock)                       [L1]
                Harness::connectL5L1Bytes(CommsChannel::VCP_UART) -> Board::initCommsBoard -> UartHardware
            connectL1L2(rawTransport)  (TracedTransport)
            ServiceDispatcher.bind(dispatchers); CommandParser(l1l2.transport, dispatcher)
        connectL2L3(dispatchers, parser)
        g_commsService.init(...)                                                 -> out.commsService
    Scheduler::initCommsTask(*out.commsService, clock, scheduler, notifier)
    Harness::setCommsRxWake(r.notifier, Scheduler::g_commsTaskHandle)  [L5 comms_board.cpp -> UartHardware::setRxWake]
  System::start()  -> vTaskStartScheduler()
```

So the *init* dependency direction is SYSTEM → L3 → (L2 → L1 → L5-bytes) and
L3 → L4 → L5 via the connect functions, plus SYSTEM → TASKS for task creation.
The *runtime call* direction is TASKS → L3 → L4 → L5 and L2 ⇄ L3 for commands.
L3 never calls into the task sheet.

## 5. RTOS objects (all static, created in `F_platform/rtos/platform_init.cpp`)

| Object | Type | Used by |
|---|---|---|
| `s_spi1Lock`, `s_spi2Lock` | `FreeRTOSMutex` (wrapped in `TracedLock` slots 0/1 by `connectSPIManager`) | `Board::g_spiManager` (SPI1 shared by motor + LCD, SPI2 flash) |
| `s_controlModeLock` | `FreeRTOSMutex` | `ControlModeManager` |
| `s_commandQueueLock` | `FreeRTOSMutex` | `Services::CommandQueue` (ARM/START queue) |
| `s_uiModeLock` | `FreeRTOSMutex` | `UI::g_uiMode` |
| `s_telemetryLock` | `FreeRTOSMutex` | `TelemetryStore` |
| `s_eventQueue` | `FreeRTOSQueue<AsyncEvent, 8>` | producer: motor path (`MotorEventManager`); consumer: `CommsService::tick` |
| `s_motorCmdQueue` | `FreeRTOSQueue<MotorCommand, 8>` (`MOTOR_CMD_QUEUE_DEPTH`) | producer: `MotorService::sendCommand` (Comms task, 50 ms bounded send); consumer: Motor task; **reset by ESTOP** |
| task notification | `FreeRTOSTaskNotifier` (`vTaskNotifyGiveFromISR` / `ulTaskNotifyTake`) | USART2 ISR → Comms task |

Lock-free cross-task state (no RTOS object): `MotorService` atomics (ESTOP latch,
stop/clear pending, debug pause, step-mode result slot), `DisplayService::m_enabled`,
`EncoderService::m_ackedIndexPulses`, and the `SeqSnapshot<IndexSnapshot>` in `Drivers::Encoder`.

FreeRTOS config: V11.1, ARM_CM4F port, heap_4, tick 1 kHz, `configUSE_TIMERS 0`,
`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY 5`, `configASSERT` defined unconditionally,
`configCHECK_FOR_STACK_OVERFLOW 2`. Hooks in `rtos/freertos_hooks.cpp`.

### Tasks (constants in `F_platform/tasks/*_task.hpp`)

| Task | Prio | Stack (words) | Loop (verbatim behaviour) | L3 entry called |
|---|---|---|---|---|
| Motor | 4 | 1024 | `delayMs(100)`; then `queue.receive(cmd, 50 ms)` → `onCommand(cmd)`; every ≥50 ms → `periodicUpdate()` | `Services::IMotorService` (`g_motorService`) |
| Comms | 3 | 2048 | `delayMs(200)`; `onStart()`; loop: `tick()`; then `rxWake->waitForNotification(10 ms)` if notifier set, else `sleepUntilMs(10)` | `Services::ICommsService` (`g_commsService`) |
| Encoder | 2 | **256** (was 128) | `sleepUntilMs(10)` → `sample()`; task not created when encoder hardware absent | `Services::IEncoderService` (`g_encoderService`) |
| Display | 1 | 640 | `sleepUntilMs(50)` → `tick()` | `Services::IDisplayService` (`g_displayService`) |

What the entries do (so the chart can show secondary fan-out):

- `MotorService::onCommand` → applies pending ESTOP/CLEAR edges; drops everything while
  debug-paused; handles `SetStepMode` itself (rewrite + atomic readback); refuses
  Move/GoTo/Run/GoHome/GoMark while the ESTOP latch is set; else
  `MotorController::processCommand`. `periodicUpdate` → pending edges; returns while
  debug-paused; else `MotorController::periodicUpdate` (control loops skipped while
  motion-inhibited) + writes `SystemTelemetry`.
- `CommsService::tick` → `ICommandProcessor::process()` + `checkBaudRevert()`; emits
  telemetry every `TELEMETRY_PERIOD_MS` if enabled; drains `s_eventQueue` → `emitEvent`;
  heartbeat timeout check.
- `EncoderService::sample` → reads the L5 DMA ring through `IEncoderHardware`, feeds
  `EncoderProcessor`, computes window velocity, reads one `IndexSnapshot` (seqlock) and
  derives `indexSeen` from pulses not yet acknowledged.
- `DisplayService::tick` → returns while disabled (LCD_DISABLE); else `handleJoystick()`;
  if `UIMode::LOCAL` → `ScreenManager::render()`.

Task suspend/resume: **none**. `Platform::IScheduler::suspendTask/resumeTask` have no
callers in `server/layers`.

## 6. ISRs and ISR→task signalling

| Vector | File | NVIC prio | What it does | Who consumes |
|---|---|---|---|---|
| `USART2_IRQHandler` | `L5_board/uart/uart_hardware.cpp` → `UartHardware::handleIRQ()` (hpp) | 6 (RTOS-safe) | push byte into SPSC ring; `m_wakeNotifier->notifyFromISR(m_wakeTask)` if set | Comms task via `UartTransport::readByte` (L1) |
| `EXTI9_5_IRQHandler` | `L5_board/isr/exti_handlers.cpp` | **5** (`ENCODER_INDEX_IRQ_PRIORITY`, static_assert ≥ max-syscall; set in `GPIO::enableExti` → `NVIC_SetPriority`) | clears PR bit 9, calls `Harness::getExtiCallback(9)` | `Drivers::Encoder::indexIsrTrampoline` → `Encoder::indexISR(tickMs, tickUs)` → `SeqSnapshot::write`; read later by `EncoderService` (task) |
| `EXTI0_IRQHandler` | `L5_board/display/te_sync.cpp` | 4 (above max syscall: flag only) | sets `s_teFlag` | `TearingSyncEXTI0::waitForEdge` polled by the ST7789 driver (Display task) |
| TIM3 + DMA1 | `L5_board/dma/encoder_sampler` | hardware only, no ISR | DMA copies `TIM4->CNT` into a 256-entry ring at 1000 Hz | `EncoderService::sample` reads write index |
| SysTick | FreeRTOS port | — | tick | scheduler |
| `HardFault_Handler` | `F_platform/rtos/freertos_hooks.cpp` | — | dump + halt | — |

ESTOP path (Comms task → Motor task): `CommandQueue::emergencyStop` → clears the staged
ARM/START queue → `IImmediateStop::immediateHardHiZ()` (`MotorService`): latch, reset
`s_motorCmdQueue`, `MotorController::emergencyHiZ()` → `IMotorDriver::hardHiZ()` on SPI1 →
then enqueues a HardHiZ command. Motor task, next pass: `MotorController::onEmergencyStop()`
(sysid abort, trim reset, supervisor idle, control loops inhibited, Hi-Z re-asserted).
`CLEAR` → `CommandQueue::clearFault` → `clearImmediateStop()`; motion accepted again from the
Motor task's next pass. `MotionService` reports `Fault` for RUN/MOVE/GOTO while latched.

## 8. Where code and docs still disagree, or what is still open (draw the code)

Resolved since the 2026-10-05 pre-Phase-3 version and no longer listed here: taps in two
places, unpublished encoder handle, L3 creating tasks, L3 board-init shims, two include
paths to `ITransport`, pins forwarders, trace as an undocumented net, `TaskHandles`.

1. **Encoder stack headroom is a static estimate, not a measurement.** The deepest chain
   plus FPU frame sums to ~350 bytes; the stack was raised to 256 words on that basis. No host
   command reports `uxTaskGetStackHighWaterMark`; only the LCD task-monitor screen shows it.
   Read it on hardware before trusting the number.
2. **SPI1 is held for the whole `DISP_BITMAP` command** (`streamBitmapStart` → UART byte
   loop on the Comms task → `streamBitmapEnd`): up to 13.3 s at 115200 baud for a full
   240×320 bitmap, 1.7 s at 921600. During that time the Motor task blocks in
   `periodicUpdate` on the SPI1 mutex and ESTOP is not parsed (same task). Proposed, not
   implemented: lock per 64-byte chunk with the ST7789 write-continue command, and an
   out-of-band ESTOP byte recognised in the USART2 ISR that aborts the stream and lets the
   Motor task perform the Hi-Z.
3. **Comms-task calls still mutate `MotorController` without a lock**:
   `MotorService::reinit/applyConfig/getDebugInfo` → `MotorController` on the Comms task while
   the Motor task may be inside `periodicUpdate`. Single SPI transactions are serialised by the
   SPI1 mutex; multi-register sequences are not. `emergencyHiZ` has a residual window: a
   command dequeued just before the latch can reach the driver; `onEmergencyStop` re-asserts
   Hi-Z within one Motor-task pass (≤ 50 ms).
4. **Four PLATFORM files define `Harness::` functions**: `F_platform/hw/early_debug_board.{hpp,cpp}`
   (`initDebugOutput`, `debugPrint*`) and `F_platform/rtos/platform_board.hpp` +
   `platform_init.cpp` (`initPlatformBoard`, `PlatformResources`). The manifest groups them by
   directory (PLATFORM), not by namespace.
5. **Global accessors exist beside the harness structs**: `Harness::microsecondClock()`
   (`pins/imicrosecond_clock`), `Harness::getExtiCallback(line)` (`pins/exti_callbacks`),
   `Services::g_telemetryStore` (written directly by `MotorController` and read by L3
   dispatchers). These are implicit edges from whoever calls them.
6. **Two ESTOP state holders.** `CommandQueue::m_state == ESTOP` (staged queue) and
   `MotorService::m_stopLatched` (motor queue + controller) are separate; `CommandQueue` is the
   only code that keeps them in step (`emergencyStop`/`clearFault`).
7. **Debug flags take effect at the next task pass, not immediately.** `LCD_DISABLE` lets a
   render in progress finish (≤ 50 ms); `SPI_STOP` lets a `periodicUpdate` in progress finish.
8. **The Comms task is one serial command loop.** Any long command delays every other host
   command, including ESTOP (this is the root of item 2).
9. **Docs archived, not deleted**: `docs/archive/` still holds the Core/Inc-era documents.
   Their content is stale. Ignore for diagramming.
